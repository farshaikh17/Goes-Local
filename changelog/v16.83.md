# v16.83-shared — the sub-category decides the main category; one main-category field (Lead Category), synced to GHL

Eric (29 Oct): "why are there incorrect sub categories in a lot of leads, also why are there 2 fields, we only need one"
→ keep **Lead Category**. Then: "We just need to ensure that it makes sense, the data from GHL can be unreliable in
terms of sub categories. So let's just fix it and get it synced on GHL as well."

## What was wrong
- The main category came from GHL's GBP Category / Lead Category (both hold the same value), set by whatever search a
  lead was imported under — e.g. 50 "Lawn care service" and 48 "Tree service" leads in Orlando under Automotive Repair,
  60 commercial real estate agencies in Miami under Beauty. The category map (`category_map`) that would let the
  sub-category decide was empty in both cities.
- The built-in keyword rules (`mainOf`) also misfire (Barber shop → Nightlife "bar", Carpet store → Pet "pet", Auto glass
  shop → Shopping "shop"), so neither source could be trusted alone.

## The decision list (docs/data/category-map.csv, 980 sub-categories from Orlando + Miami)
- Where GHL's majority and the rules agreed (483), kept. The rest decided by `scripts/category-decide.cjs`: medical
  specialists → Medical, oral surgeons → Dental, vets → Pet, vehicle repair shops → Automotive Repair, home-improvement
  stores → Contractors & Construction, barbers / brow bars / make-up / massage → Beauty, real estate & apartments → Real
  Estate & Housing, plus an explicit list for the rest. ~1,300 Orlando and ~1,700 Miami listings change main category.
- Loaded into each city's `category_map` (docs/data/category-map.sql). The site already lets that map win (norm), so
  listings move on the next sync pass; sync records the old addresses as redirects (recordSlugChange).

## Code
- `norm` reads Lead Category first; GBP Category / Business Category only when it is empty.
- Owner/admin category edits and new contacts write Lead Category (FMAP category, publish/import paths).
- Sync queues every contact whose GHL Lead Category differs from the category the site settled on (`lead_cat_fix`);
  `leadCatBatch` writes 40 per cron run (custom field only), stops on 429; `meta leadcat_pause=1` pauses it.
