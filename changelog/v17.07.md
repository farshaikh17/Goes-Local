## Change
- New per-site Variable `CITY_SYNC_COOLDOWN_MIN` (whole minutes 5–1440; unset/invalid = 10, the old fixed value):
  minutes the 5-minute cron waits after a successfully completed full pass before STARTING the next one.
  A pass in progress resumes every tick regardless; only a completed pass writes `synced_at`, so a failed or partial
  pass never starts the wait. First sync, manual Run sync (/admin/sync), the lock, retries, paging, batch sizes
  (30 pages/tick) and the cron (*/5) are unchanged. The sync is still the last job of the tick, so a skipped sync
  never stops the other jobs.
- One aggregate log line per tick: `cron: sync=started|resumed|completed|failed|skipped-cooldown` with pages,
  contacts read, listings changed (rows written because they differed from what was stored — the sync already
  skips unchanged contacts — or are new / back after a missed pass) and wall time (not CPU). No contact data;
  emails are masked in the failure message. No extra reads.
- Pilot: set `CITY_SYNC_COOLDOWN_MIN=60` on goes-local-orlando-api only (dashboard Variable; keep_vars keeps it).
