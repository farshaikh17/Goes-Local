# v17.05-shared — duplicate merge: fix the opportunities check

v17.04's first live preview (Miami, 20 pairs, 13 Nov) stopped every pair as "manual — couldn't check
opportunities/appointments". GHL's /opportunities/search takes `locationId` and `contactId` (camelCase); v17.04 sent
`location_id`/`contact_id` and got 422. Confirmed with the GHL API: the camelCase call returns 200 (0 opportunities for a
sample contact) and /contacts/{id}/appointments returns 200 with `events`.

## Change
- `mergePair`: opportunities search uses locationId/contactId and status=all (open, won, lost and abandoned all count).
- When a check can't run, the reason shows both HTTP statuses, e.g. "couldn't check opportunities (403) / appointments (200)".
- Nothing was merged or changed by the v17.04 preview (dry run).
