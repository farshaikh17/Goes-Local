# v16.88-shared — Meta Pixel actually loads (fix for v16.86)

Eric (2 Nov): Miami's Pixel (1893063295472643, added as CITY_META_PIXEL) showed "empty, 0% progress" in Events Manager.
Cause: the site's Content-Security-Policy only allows scripts and connections from Google, jsDelivr and Cloudflare, so
browsers refused `connect.facebook.net/en_US/fbevents.js` ("violates the following Content Security Policy
directive: script-src …", seen on the live Miami worker). The v16.86 check only looked for the Pixel code in the page.

## Change
- When the city has a Pixel, the security header also allows `https://connect.facebook.net` (scripts) and
  `https://connect.facebook.net https://www.facebook.com` (connections). Cities without a Pixel keep the tighter header.

## Tests
- 87/87 local (new T43b: the header allows the Pixel). In a real browser on the local site the Pixel script loaded,
  `fbq` initialised, and `facebook.com/tr?…ev=PageView` returned 200.

## Status
- Live on Orlando and Miami (2 Nov, Eric: "Go ahead, put v16.88 live"). On the live Miami worker the Pixel script and
  config load and `facebook.com/tr?id=1893063295472643&ev=PageView` returns 200. Note: Miami's Pixel has Meta's
  BotBlocking on, so headless test browsers send nothing — test with a normal browser user agent.
